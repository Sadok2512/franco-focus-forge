# Signaling feature rules

- Network Events uses a frontend presentation allowlist in `network-events.ts`; other tracks, capture duration, source events and message queries remain independent of that allowlist.
- Signaling cursor uses one capture-time state in SignalingPage and a single ECharts pixel overlay across all RF grids; cursor motion is local so selection never becomes a list query key or triggers details requests.
- Signaling starts its cursor at capture time zero without selecting a message; pixel overlays refresh on chart readiness and resize, and hover previews never replace the locked cursor.
- Signaling visible time and TimeNavigator are shared by all timeline views in SignalingPage; both /signaling and /signaling-v2 use the UE/RRC State layout with the configurable 30 s initial window (user request to match the V6 mockup). Zoom changes are local and never message/map query keys.
- Navigator edge resizing uses a pure boundary-clamping helper and capture-coordinate pointer deltas; it changes only the shared visible window, never cursor or message state.
- RF timeline owns its TimeNavigator inside the chart scroll region so it remains attached to the tracks during resizing and fullscreen; other views retain the shared page navigator. The timeline shows no evidence row under the chart (user request) — selection details stay in the tooltip, inspector and message table.
- Signaling V2 validates supplied state intervals in `state-evidence.ts` only, never reconstructs them from nearby messages; both boundary sequences, capture/session identity, technology and versioned source rules are required, and carrier labels require separate explicit CA evidence. This keeps Unknown honest until the VM evidence contract is validated.
- The proven LTE context rule accepts the opening RRA or the intermediate RRC as event seq while retaining the full ordered source chain and release boundary; UE and RRC states are validated separately so RF pivot serialization cannot hide proven bands or invent states.
- Signaling timeline tracks resolve from `attrs.track` with the VM's canonical `lane` as fallback (`event-track.ts`), and events carrying no protocol attribute bypass the protocol layer filter; icons are mapped in `event-icons.tsx` from supplied types and tracks, with Lucide SVG images kept inside ECharts event groups to preserve exact message selection and time alignment.
- Signaling always retains UE/RRC lanes; `state-evidence.ts` validates source intervals and `state-presentation.ts` maps only proven configurations/modes, with count/status qualifiers and no band inference. Unknown areas stay uncolored, evidence remains accessible on selection, and simultaneous LTE/NR use separate subbands until a combined-mode contract is validated. RF cursor readouts and other tracks remain independent.
- Signaling click feedback is a name-only chip (`name-tag.ts`): a clicked event or RF measurement shows its name and nothing else, measurements resolve to the nearest plotted point within 14 px, and the chip is cleared by a blank click, a pan/zoom or Escape. Details stay in the message table and inspector so the chip never becomes a second payload viewer.
- Signaling messages table columns, Info/RRC/radio association and column persistence live in `message-columns.ts`; Info shows only VM procedures, RRC State only proven intervals, radio only the previous real observation, and unsupplied fields (band, cell name) render "—" so the table never fabricates values.
- Signaling message-type filtering uses a complete paginated rows population through client.ts, cached per capture for counts; transactional draft selection is isolated from timeline/map keys, and exact name+layer filtering, pagination and CSV share the same selected population. Reject incomplete/changing populations so capture counters cannot become page counts.
- Signaling message filter hierarchy (Technology → Channel → Message) is built in `message-filter.ts`; RRC channels come from the decoded VM `channel` first, then the exact-match 3GPP TS 36.331/38.331 catalogue in `rrc-channels.ts` (controlled normalisation, no substring matching), else Unclassified; NAS/Nemo/MAC never get RRC channels and conflicts keep the source channel.
- Signaling page shows no header strip: the view switch and the timeline/map activations live in the filters sidebar (`.sig-filters-view`) and, when the sidebar is collapsed, as icon toggles in the rail, so the workspace fills the window; `.signaling-workspace` height offsets only the app bar and page padding, so any change to that chrome must keep the `calc()` offset in sync to avoid page scroll or lost space.
- Signaling messages toolbar keeps the counter first and unclipped: `.sig-count` is `flex: 0 0 auto` with nowrap so a long count always fits the first line, the search box is a compact flexible field (130–220 px), and the columns/export/clear actions render icon-only (`.sig-tool-icon`) with their name — and the columns visible/total count — carried by `aria-label`/`title` instead of visible text.
- The Signaling map reuses the KPI Sites layer (`@/features/kpi/SitesLayer` + `SitesLayerControls`): the persistent Sites ON/OFF toggle sits top-right, the fullscreen button shifts left to make room, and the layer loads lazily by bbox without touching the GPS track or geolocated events. The embedded map passes `sitesMinZoom: 12` so site points (and their fetch) only appear from zoom 12 — user choice to keep the GPS track readable; presentation only, never clustering, and the Map page keeps sites at every zoom.
- Signaling hands the drive RSRP layer the positions of its own already-fetched `points` view (`rsrpPositionsFrom(data.points, data.markers)`) instead of issuing a second GPS request, so an RSRP row without a position of its own can still be drawn at its exact sequence; the layer never moves the investigation camera and never invents a position.
