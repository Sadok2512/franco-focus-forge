# KPI workspace rules

- KPI and metric selections persist together per workspace tab; legacy URL metrics migrate only to the active tab, so new tabs are empty and switching restores each tab's panels.
- Metrics shares KPI catalog/card classes and design-system controls; presentation changes must leave metric analysis queries and capture filters unchanged.
- Measurements loading uses an accessible indeterminate progress bar in a compact initial table placeholder and at the existing table's top edge during refresh; never fabricate percentages or change panel identity for loading presentation.
- The Metrics pane renders no toolbar of its own (no view/per-row/export/fullscreen row above it): the big table is an extra panel added by the catalogue row menu (`paneRequest`) next to the graph cards, never replacing them; its open state persists per workspace tab and its own close button removes only it — and Table titles use API metric and cell labels, never a hardcoded example. A metric whose catalogue ⋮ view is `table` gets no graph card at all (it exists only in the measurements table); per-metric views persist per workspace tab in `metric-views.ts`, and a workspace with nothing left to graph offers the table through a button instead of showing an empty grid. The table panel carries the shared `WorkspacePanelMenu` (⋮) inside its own header — Export CSV from the API response, Fullscreen on the panel element, Close panel — so panel actions never need a new toolbar row.
- Workspace Table Settings live in `table-settings.ts` (per workspace tab, localStorage), reach every workspace table (Metrics pane, Metrics card tables, KPI data table) through `TableSettingsWorkspaceContext` + `tableSettingsProps`, and are opened from the ⚙ in the active bottom tab; they change presentation only (CSS vars, column order/visibility, sort/search) and never values, queries or exports. Edits stay in a dialog draft and reach the tables only when the user clicks "Appliquer", so closing the popup discards them.
- WorkspaceGrid derives columns solely from the active tab layout and observed container width; Metrics wrappers use display:contents so PanelShell frames share the grid. Clamp spans to derived columns; never use nested metric grids or resize-driven query keys. Layout/title/order persist per tab.
