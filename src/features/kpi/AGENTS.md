# KPI workspace rules

- Beam size and opacity are presentation-only percentages in the shared Sites display state: rebuild sector geometry locally for radius changes and update paint for opacity, never refetch sites or change RF azimuths, coordinates, filters or multi-band slices.

- Metric Map selections render independent map cards using the analysis API with `include_map: true` for the active capture and selected parameter; never fall back to a graph or change the measurements table's view. Catalogue and panel view changes share the per-tab metric view state.
- KPI and metric selections persist together per workspace tab; legacy URL metrics migrate only to the active tab, so new tabs are empty and switching restores each tab's panels.
- Metrics shares KPI catalog/card classes and design-system controls; presentation changes must leave metric analysis queries and capture filters unchanged.
- Map cards (KpiMapOSM) must set the MapLibre v6 worker explicitly via `setWorkerUrl` AND the map div must fill its wrapper with inline `position: absolute; inset: 0` — a `h-full` div collapses to 0 px inside a parent that only has `min-height`, leaving a white canvas; MapLibre's own stylesheet forces `position: relative`, so a class alone cannot override it.
- KPI metric-card maps render every geolocated measurement as an unclustered MapLibre circle coloured by its numeric value; their legend carries the metric label, unit and colour scale. This explicit coverage view must never reintroduce count bubbles. Other measurement-map implementations retain their own documented clustering policy. The metric map still frames the real point extent via fitBounds, while Sites remain a separate unclustered source/layer.
- The Sites layer never clusters: every site renders as an individual point at every zoom (no `cluster` option, no cluster layers, no expansion click), cells/sectors stay unclustered, and server `kind:"cluster"` aggregates are dropped; performance comes from bbox-scoped fetches with abort + debounce and the `MAX_SITE_FEATURES` cap, never from grouping. The only zoom gate is the optional `sitesMinZoom` option (used by the embedded Signaling map at 12) which hides site points below that zoom without grouping them. Every map style using symbol labels must set `glyphs: MAP_GLYPHS`, otherwise symbol layers fail silently.
- A multi-band cell (several bands on one physical sector — same site, azimuth and position, or a `bands` array on the feature) renders as one sector split into contiguous colored slices, one per band, via `getGeorefSectorSliceCoords`; all slices share the same `cell_key` so selection highlights the whole sector, and the cell point is deduplicated to one per sector carrying the full `bands` list for the popup. Never stack full-aperture single-color sectors on top of each other.
- Operator identity goes through `operatorKey`/`operatorLabel` only: the API returns readable names (`Bouygues`) while filters, legend and colours use codes (`BYT`), so a raw `operator` match silently drops three of the four operators into the unknown grey — normalise to `op_key` on each feature before it reaches the map.
- Measurements loading uses an accessible indeterminate progress bar in a compact initial table placeholder and at the existing table's top edge during refresh; never fabricate percentages or change panel identity for loading presentation.
- The Metrics pane renders no toolbar of its own (no view/per-row/export/fullscreen row above it): the big table is an extra panel added by the catalogue row menu (`paneRequest`) next to the graph cards, never replacing them; its open state persists per workspace tab and its ⋮ Remove action removes only it (no title, no ✕ button) — and Table titles use API metric and cell labels, never a hardcoded example. A metric whose catalogue ⋮ view is `table` gets no graph card at all (it exists only in the measurements table); per-metric views persist per workspace tab in `metric-views.ts`, and a workspace with nothing left to graph opens the measurements table on its own (top of the pane when alone) — never a hint message, an empty grid, or a "show table" button. The table panel carries the shared `WorkspacePanelMenu` (⋮) inside its own header — Export CSV from the API response, Fullscreen on the panel element, Close panel — so panel actions never need a new toolbar row. That ⋮ chip must stay anchored fully inside the panel box (the panel clips overflow: a chip translated over the border is invisible and unclickable) and reserve width in the last header column so no column name hides under it.
- Workspace Table Settings live in `table-settings.ts` (per workspace tab, localStorage), reach every workspace table (Metrics pane, Metrics card tables, KPI data table) through `TableSettingsWorkspaceContext` + `tableSettingsProps`, and are opened from the ⚙ in the active bottom tab; they change presentation only (CSS vars, column order/visibility, sort/search) and never values, queries or exports. Edits stay in a dialog draft and reach the tables only when the user clicks "Appliquer", so closing the popup discards them.
- WorkspaceGrid derives columns solely from the active tab layout and observed container width; Metrics wrappers use display:contents and each metric graph has its own PanelShell so no legacy per-row preference can override the active layout. Tables reserve grid lines 1 / -1 regardless of saved spans; other spans clamp to derived columns. Every table sits below all graph panels: `sunkPanelOrder` adds `TABLE_PANEL_ORDER` to full-row panels and the measurements table divs carry that order, so no saved panel order can lift a table above a graph. Never use nested metric grids or resize-driven query keys. Layout/title/order persist per tab.
- Events bar clicks toggle events in one shared per-workspace/capture state (`active-events.tsx`, stable ids capture:type:seq); graphs draw ReferenceLines only for their own capture and tables highlight exact t_rel_s matches only — never nearest rows, never new queries.
- The Map page and Signaling View share one premium chrome (`NetworkMapChrome`, enabled by `KpiMapOSM workspace`) over the same Sites layer and GEOREF beams; its layer toggles, search and tools only drive the existing map and /sites results, and features the API does not provide (site types, 3G, heatmap) stay disabled rather than invented.
- Initialize Sites overlays as soon as the map style is parsed, not after `isStyleLoaded()` becomes true: pending satellite raster tiles must never block site sources or their first bbox request.
- Workspace maps (`KpiMapOSM workspace`) must follow the project centre when it resolves after map creation (fly to the changed `center` prop once ready): the project query resolves asynchronously, and without the fly the map stays at the default France view while the project's sites sit outside the opening viewport.
- The Map page's drive RSRP layer (`DriveRsrpLayer`) is a toggleable unclustered coverage layer coloured by `drive-rsrp.ts` classes: it reads `map_points` of the metrics analysis (`include_map: true`, metric `cell_rsrp`) and, when those carry none, the same response's table rows that hold both server lat/lon and a measured RSRP; a row whose own position is empty is placed on the capture's GPS log (the `signaling points` view the page already has, or one extra `points` request on the Map page) at the exact same sequence and nowhere else — never interpolated, nearest-in-time or invented; the RSRP column is matched as `cell_rsrp@<cell>` for any cell index (lowest measured cell wins) and the popup names that cell plus where the position came from; points without a numeric value are dropped, the layer sits below the Sites layers, a capture is remembered as the default only when it really produced points, and its on/off, size and intensity persist in localStorage — classifying measurements by colour is why it is exempt from measurement clustering.
- RSRP-to-serving-cell lines use only the API proof `chi_previous_seq_cell_ref_exact`: the last LTE CHI Cell ID in the same capture and canonical seq order must match `cell_ref.eci` exactly and carry a reference geometry. Never connect a point to a nearest site, a PCI-only candidate, or another operator/band approximation; an unproved point remains visible without a line.
