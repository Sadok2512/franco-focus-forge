# KPI workspace rules

- Metric Map selections render independent map cards using the analysis API with `include_map: true` for the active capture and selected parameter; never fall back to a graph or change the measurements table's view. Catalogue and panel view changes share the per-tab metric view state.
- KPI and metric selections persist together per workspace tab; legacy URL metrics migrate only to the active tab, so new tabs are empty and switching restores each tab's panels.
- Metrics shares KPI catalog/card classes and design-system controls; presentation changes must leave metric analysis queries and capture filters unchanged.
- Map cards (KpiMapOSM) must set the MapLibre v6 worker explicitly via `setWorkerUrl` AND the map div must fill its wrapper with inline `position: absolute; inset: 0` — a `h-full` div collapses to 0 px inside a parent that only has `min-height`, leaving a white canvas; MapLibre's own stylesheet forces `position: relative`, so a class alone cannot override it.
- Measurement points on maps (MetricMap, KpiMeasurementMap) are always clustered (`cluster: true`, graduated clusters with count, click-to-zoom, individual points only at high zoom) and the metric map frames the real point extent via fitBounds — never render thousands of raw circles, they merge into an unreadable blob.
- Measurements loading uses an accessible indeterminate progress bar in a compact initial table placeholder and at the existing table's top edge during refresh; never fabricate percentages or change panel identity for loading presentation.
- The Metrics pane renders no toolbar of its own (no view/per-row/export/fullscreen row above it): the big table is an extra panel added by the catalogue row menu (`paneRequest`) next to the graph cards, never replacing them; its open state persists per workspace tab and its ⋮ Remove action removes only it (no title, no ✕ button) — and Table titles use API metric and cell labels, never a hardcoded example. A metric whose catalogue ⋮ view is `table` gets no graph card at all (it exists only in the measurements table); per-metric views persist per workspace tab in `metric-views.ts`, and a workspace with nothing left to graph opens the measurements table on its own (top of the pane when alone) — never a hint message, an empty grid, or a "show table" button. The table panel carries the shared `WorkspacePanelMenu` (⋮) inside its own header — Export CSV from the API response, Fullscreen on the panel element, Close panel — so panel actions never need a new toolbar row. That ⋮ chip must stay anchored fully inside the panel box (the panel clips overflow: a chip translated over the border is invisible and unclickable) and reserve width in the last header column so no column name hides under it.
- Workspace Table Settings live in `table-settings.ts` (per workspace tab, localStorage), reach every workspace table (Metrics pane, Metrics card tables, KPI data table) through `TableSettingsWorkspaceContext` + `tableSettingsProps`, and are opened from the ⚙ in the active bottom tab; they change presentation only (CSS vars, column order/visibility, sort/search) and never values, queries or exports. Edits stay in a dialog draft and reach the tables only when the user clicks "Appliquer", so closing the popup discards them.
- WorkspaceGrid derives columns solely from the active tab layout and observed container width; Metrics wrappers use display:contents and each metric graph has its own PanelShell so no legacy per-row preference can override the active layout. Tables reserve grid lines 1 / -1 regardless of saved spans; other spans clamp to derived columns. Every table sits below all graph panels: `sunkPanelOrder` adds `TABLE_PANEL_ORDER` to full-row panels and the measurements table divs carry that order, so no saved panel order can lift a table above a graph. Never use nested metric grids or resize-driven query keys. Layout/title/order persist per tab.
- Events bar clicks toggle events in one shared per-workspace/capture state (`active-events.tsx`, stable ids capture:type:seq); graphs draw ReferenceLines only for their own capture and tables highlight exact t_rel_s matches only — never nearest rows, never new queries.
